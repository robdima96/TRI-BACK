# TRI-BACK Knowledge Graph Traversal & RAG — Improvement Specification

You are a senior Python engineer working on the **TRI-BACK** clinical triage chatbot (`bot/`). Your task is to **improve and integrate** the knowledge-graph traversal and RAG retrieval pipeline so it matches the study-app requirements in `prototypes/prompt_2.txt` and the clinical design below.

Work **only** in `bot/app/services/rag/`, `bot/app/services/graphrag/`, and the minimum orchestrator wiring needed (`bot/app/orchestrator/`, `bot/app/schemas.py`, `bot/app/main.py`). Do not build the Reflex study UI (`prototypes/tri_back_study_app/`). The study app will consume your outputs via `POST /api/v1/chat` once exposed on `ChatResponse`.

---

## 1. Target clinical behaviour (three coordinated inputs)

Each chat turn must run a **unified retrieval-and-traversal pipeline** with three legs:

| Leg | Input | Method | Output |
|-----|-------|--------|--------|
| **A — Factor matching** | Merged `clinical_checklist` items from the encoder | **Regex / pattern rules** mapped to canonical **Factor** node names | `list[FactorMatch]` with `factor_name`, `match_method`, `match_score`, source checklist row |
| **B — Chunk matching** | Normalized user message (`message_normalized`) | **Semantic sentence embedding** (Clinical_sBERT via existing `compute_query_embedding`) against Chroma | `list[Evidence]` with `chunk_id`, `source`, `snippet`, `score` |
| **C — Graph traversal** | Matched **Factors** (leg A) **and** matched **Chunks** (leg B) | **Local in-memory walk** over red-flags v1 graph loaded from `Graphs/backups/red flags/v1/` (CSV + inventory) — **no live Neo4j in `bot/`** | `GraphTraversalTrace` with `candidate_conditions`, ordered `steps`, Cytoscape-ready `nodes`/`edges`/`highlight` |

**End goal:** traverse from identified chunks and factors to **target Condition nodes** — `Fracture`, `Malignancy`, `Infection`, `CES`, `AAA`, `DVT` — to support triage disposition (emergency vs conservative management). Citations shown to users must correspond to **Chunk nodes that were actually traversed or semantically retrieved**.

### 3.1 Graph schema (v1)

**Node labels:**

- `Factor` — symptoms, demographics, comorbidities, triggers, mediators (`name` unique)
- `Condition` — `Fracture`, `Malignancy`, `Infection`, `CES`, `AAA`, `DVT`
- `Chunk` — evidence text (`chunk_id` unique); properties include `chunk_string`, `path_type`, `is_specific`, `evidence`, `loc`

**Relationship types:**

- Factor → Condition: `RISK_FACTOR_FOR`, `SUGGESTIVE_OF`, `ASSOCIATED_WITH`, `TRIGGER_FOR`, … (from CSV `edges` column)
- Factor → Factor (mediator) → Condition: `path` mediator + `CONTRIBUTES_TO`
- Chunk → Factor: `DESCRIBES`
- Chunk → Condition: `APPLIES_TO`

**Path types:**

- `direct`: `Factor -[edges]-> Condition`
- `mediated`: `Factor -[edges]-> Factor(path) -[CONTRIBUTES_TO]-> Condition`
- `both`: creates direct and mediated edges

### 3.2 Inventory facts (do not hardcode stale counts — load from `inventory.json`)

- 48 Factors (e.g. `Recent trauma`, `Severe pain`, `Bladder dysfunction`, `Age over 50`, `IV drug user`, …)
- 6 Conditions with varying chunk coverage (Fracture 18, DVT 12, Infection 12, Malignancy 11, AAA 8, CES 5)
- 66 Chunks with ids `r_1` … `r_66`
- Known data quirk: inventory lists both `Immunosuppresion` and `Immunosuppression` — normalize in matchers

## 4. Current implementation — what exists today

### 4.1 Orchestration (`bot/app/orchestrator/`)

LangGraph flow (`graph.py`):

```
START → preprocess_input → ingest_input → encode_input → evaluate_coverage
  → plan_question → [generate_question | retrieve_evidence | policy_gate]
  → generate_draft → policy_gate → finalize_response → END
```

**Critical gap:** `traverse_from_checklist` / GraphRAG is **not called** anywhere in the live graph. Only `retrieve_evidence_node` runs RAG.

Relevant state (`state.py`):

- `clinical_checklist: list[dict]` — merged across turns
- `encoder_pooled_embedding: list[float]` — Clinical_sBERT vector of full message
- `evidence: list[Evidence]` — RAG results (no `chunk_id` on `Evidence` model today)

`retrieve_evidence_node` (`nodes.py`):

```python
state["evidence"] = retrieve_evidence(
    state["message_normalized"],
    state.get("encoder_pooled_embedding") or None,
)
```

### 4.2 Encoder / checklist (`bot/app/services/encoder.py`)

Produces `ChecklistItem` rows with:

- `text`, `kind`, `source` (`pattern` | `gliner` | `safety_phrase`), `label`

Regex patterns already extract: comorbidities, duration, age, sex, severity, night pain, weight-bearing pain, etc. GliNER adds span entities. This is the **input** to factor matching — do not duplicate encoding logic in RAG; consume `clinical_checklist`.

### 4.3 RAG (`bot/app/services/rag/`)

| Module | Current behaviour |
|--------|-------------------|
| `embeddings.py` | `compute_query_embedding(text)` — Clinical_sBERT, dim 768 |
| `store.py` | Chroma sub-collections: `red_flags`, `clinical_guidelines`, `clinical_vignettes`, `conversation_templates`, `diagnostic_confounders` |
| `__init__.py` `retrieve_evidence()` | Embeds **full normalized user message**; queries all sub-collections; returns top-k `Evidence(source, snippet, score)` — **no `chunk_id` in schema** |
| `retrieval_query.py` | Entity phrase builders for **offline benchmarks only**; production path uses full message, not per-entity |
| `chunk_and_ingest.py` | Ingests CSV registries; metadata includes `chunk_id`, `source`, `sub_collection` |

**Gap vs target:** Leg B (semantic chunk match) works but is **disconnected** from graph Chunk nodes and from factor matching. Leg A (checklist → Factor regex) is **not in RAG** — it lives partially in `graphrag/factor_matcher.py` with a different strategy.

**Toggle:** `TRI_BACK_LOAD_GRAPHRAG` / `settings.graphrag_load` — when false, skip graph traversal entirely; when true, use **local** v1 graph (not Neo4j).

### 5.2 Leg A — Checklist → Factor regex matching (in `rag/`)

**Requirements:**

1. Load canonical Factor names from `Graphs/backups/red flags/v1/inventory.json` (same path as `neo4j_config.DEFAULT_INVENTORY_PATH`).
2. Build a **maintainable regex registry** — not one giant opaque dict — with entries like:

```python
@dataclass
class FactorPattern:
    factor_name: str
    patterns: list[re.Pattern[str]]
    checklist_kinds: frozenset[str] = frozenset()   # optional filter
    checklist_labels: frozenset[str] = frozenset()  # e.g. ("comorbidity", "diabetes")
    priority: int = 0
```

3. **Derive patterns from three sources:**
   - **Encoder alignment:** map `encoder.py` kinds/labels to Factors (e.g. `("severity", "symptom_severity")` → `Severe pain`; `("demographic", "age")` + age≥50 → `Age over 50`)
   - **Factor name variants:** auto-generate case-insensitive patterns from inventory names (e.g. `Calf swelling`, `calf swell`)
   - **Clinical aliases:** fever/temperature → `Fever`; fall/trauma → `Recent trauma`; saddle numbness → `Saddle anaesthesia` (extend current `_TEXT_ALIASES` comprehensively using CSV `source_nodes` column as ground truth)

4. Run matchers against each `ChecklistItem.text` **and** optionally against `(kind, label)` metadata before regex on text.
5. Return `FactorMatch` objects (reuse `graphrag/schemas.py:FactorMatch` or re-export from `rag/`).
6. **Prefer regex specificity over fuzzy overlap** — demote or remove the token-overlap fuzzy matcher for production; keep fuzzy only as fallback with high threshold and `match_method="fuzzy_fallback"`.
7. Emit `match_method`: `regex`, `checklist_kind`, `alias`, `factor_name_exact`.

**Migrate** existing logic from `graphrag/factor_matcher.py` into `rag/factor_matcher.py`; leave `graphrag` importing from `rag` to avoid duplication.

### 5.3 Leg B — Semantic chunk retrieval (enhance existing `rag/`)

**Requirements:**

1. Keep embedding the **full normalized user message** via `compute_query_embedding` (existing behaviour).
2. Query Chroma sub-collection **`red_flags` first** (primary corpus aligned with graph v1); optionally merge `clinical_guidelines` with lower weight.
3. Extend `Evidence` or add `ChunkMatch`:

```python
class ChunkMatch(BaseModel):
    chunk_id: str
    source: str
    snippet: str
    score: float
    sub_collection: str
```

4. Parse `chunk_id` from Chroma metadata (`metadatas[].chunk_id`) — already stored at ingest time.
5. Validate retrieved `chunk_id` values exist in graph v1 inventory (`r_1`…`r_66`); flag unknown ids in logs.
6. **Optional enhancement:** also embed top checklist item phrases (`retrieval_query.py:entity_retrieval_phrases`) and merge results via RRF or max-score — but full-message embedding remains the primary query.

### 5.4 Leg C — Local graph traversal from Factors **and** Chunks (`graphrag/`)

**Primary implementation: `LocalGraphClient` in `local_graph.py`**

Load the v1 graph once at startup (or `@lru_cache`) from:

```
Graphs/backups/red flags/v1/source/red_flags_manual_failsafe.csv
```

Reuse `Graphs/graph_builder.py:ChunkRow` / `load_chunks()` parsing logic (import or duplicate minimally in `bot/` to avoid coupling to `Graphs/` runtime). Build in-memory indexes:

- `by_factor: dict[str, list[ChunkRow]]` — keyed by `source_nodes` (case-insensitive)
- `by_chunk_id: dict[str, ChunkRow]`
- `by_condition: dict[str, list[ChunkRow]]` — keyed by `parent_id`
- `by_mediator: dict[str, list[ChunkRow]]` — keyed by `path` when `path_type` is `mediated` or `both`

**Implement on `LocalGraphClient` (same `PathSegment` shape as today):**

1. **`paths_for_factors(factors: list[str]) -> list[PathSegment]`**

   - Filter CSV rows where `source_nodes` matches a seed factor (case-insensitive)
   - For each row, emit direct path (`path_type` `direct` or `both`) and/or mediated path (`path_type` `mediated` or `both` with `path` mediator)
   - Map row fields to `PathSegment` (factor, condition, relationship=`edges`, mediator=`path`, chunk_id, chunk_string, path_type, is_specific)
   - Use **synthetic stable element IDs** for Cytoscape (e.g. `hash("Factor", name)`, `hash("Chunk", chunk_id)`) — Neo4j `elementId` not required

2. **`paths_for_chunks(chunk_ids: list[str]) -> list[PathSegment]`**

   - Lookup rows by `chunk_id`; each row already encodes Chunk `DESCRIBES` Factor and `APPLIES_TO` Condition
   - Return path segments for the row's factor → condition chain(s)

3. **`paths_for_seeds(factors: list[str], chunk_ids: list[str]) -> list[PathSegment]`**

   - Union `paths_for_factors` and `paths_for_chunks`
   - Dedupe by `(factor, condition, relationship, mediator, chunk_id)`
   - Prefer paths where **both** a matched Factor and a retrieved Chunk support the same Condition

4. **`build_subgraph(segments) -> (nodes, edges)`**

   - Build `GraphNode` / `GraphEdge` lists from segments without Neo4j (reuse `elements.py` helpers)

**Do not call Neo4j from `bot/` for chatbot traversal.** The existing `Neo4jGraphClient` in `graph_client.py` may remain for `Graphs/` tooling parity but must not be the default in `orchestrator.py` or LangGraph nodes.

5. **Condition aggregation** (`condition_ranker.py`):

   - Input: all `PathSegment` rows
   - Output: ranked `candidate_conditions` with evidence counts per condition
   - Weight: `is_specific=true` chunks higher; `TRIGGER_FOR` / `SUGGESTIVE_OF` edges weighted per clinical urgency (CES, AAA, Infection > chronic Fracture risk factors)
   - Do **not** auto-diagnose — output supports policy/disposition, not definitive labels

4. **Extend `traverse_from_checklist`** → rename or wrap as **`traverse_from_turn`**:

```python
def traverse_from_turn(
    *,
    checklist: list[ChecklistItem] | list[dict],
    chunk_matches: list[ChunkMatch],
    trace_id: str | None = None,
    title: str | None = None,
) -> GraphTraversalTrace:
```

   Steps in trace (auditable):

   1. `checklist_item` — each checklist row
   2. `match_factor` / `unmatched` — from leg A
   3. `match_chunk` — each semantically retrieved chunk (new action)
   4. `traverse_direct` / `traverse_mediated` / `evidence_link` — from local CSV rows
   5. `aggregate_conditions` — ranked candidates

6. **Default graph backend:** `TRI_BACK_GRAPH_BACKEND=local` (default). Optional `neo4j` value exists only for dev comparison against `Graphs/` — not required for study deployment.

### 5.5 Fusion layer (`rag/fusion.py`)

def build_traversal_seeds(
    checklist: list[ChecklistItem],
    message_normalized: str,
    query_embedding: list[float] | None,
    *,
    top_k_chunks: int = 10,

- Deduplicate factors and chunks
- Merge chunk citations: semantic hits + chunks linked via graph traversal
- Return unified `list[Evidence]` for `generate_draft_node` where citations are **only** chunks that appear in seeds or trace

### 5.6 Orchestrator integration

Add **`graph_traversal_node`** after `encode_input_node` and **`retrieve_evidence_node`** (or combine retrieve + traverse in one node to avoid duplicate embedding):

**Recommended graph change:**

```
evaluate_coverage → plan_question → ...
  retrieve_evidence → graph_traversal → generate_draft → ...
```

`graph_traversal_node`:

```python
def graph_traversal_node(state: ChatState) -> ChatState:
    from app.services.rag.fusion import build_traversal_seeds
    from app.services.graphrag import traverse_from_turn

    seeds = build_traversal_seeds(
        checklist=state.get("clinical_checklist") or [],
        message_normalized=state["message_normalized"],
        query_embedding=state.get("encoder_pooled_embedding"),
    )
    trace = traverse_from_turn(
        checklist=state.get("clinical_checklist") or [],
        chunk_matches=seeds.chunk_matches,
    )
    state["matched_factors"] = trace.matched_factors
    state["candidate_conditions"] = trace.candidate_conditions
    state["traversed_chunk_ids"] = seeds.chunk_ids_in_trace(trace)
    state["graph_traversal"] = trace.model_dump()
    state["evidence"] = seeds.evidence_for_generator  # graph-aligned citations
    return state
```

**Question-mode path:** when `plan_question` routes to `generate_question`, skip graph traversal (no disposition yet) OR run lightweight factor matching only — document choice; default **skip full traversal during intake questions**.

Wire `TRI_BACK_LOAD_GRAPHRAG=0` to skip traversal entirely but still run regex factor matching + semantic chunk retrieval.
